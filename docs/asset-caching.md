# Static asset browser caching

Cloudflare Workers Static Assets reads `public/_headers`, copied by Astro to
`dist/_headers` during the build. The `/_astro/*` rule overrides the default
`Cache-Control` with `public, max-age=31536000, immutable` for Astro's fingerprinted
assets. A changed asset receives a new URL, so it is safe to cache for one year.

`/link-card-images/*` is deliberately excluded: `cacheImage()` in
`src/lib/markdown/link-card.ts` hashes the decoded source URL, not the downloaded
bytes. A remote image can change without changing its local filename.

HTML, favicon, and Partytown's stable URLs retain Cloudflare's default
`public, max-age=0, must-revalidate` policy. Do not add a site-wide immutable rule.

`wrangler.toml` runs the Worker first only for `/posts/*`. The `/_astro/*` assets
therefore use the static asset rules directly, including when referenced by a
post. No Worker header changes are needed. `src/worker.ts` delegates post delivery
to `env.ASSETS.fetch()` and preserves existing headers when adding `Vary: Accept`
or the Markdown charset. Headers on responses generated by Worker code must be
set in that code; `_headers` is not a general Worker response middleware.

See [Cloudflare's Workers Static Assets headers documentation](https://developers.cloudflare.com/workers/static-assets/headers/)
for `_headers` support, overrides, and the Worker-generated response caveat.

To check the deployed behavior locally, run `pnpm run build:ci`, then
`pnpm exec wrangler dev`. Inspect a generated CSS or image URL under `/_astro/`
with `curl -I`, and compare it with `/posts/nespresso-mold/`, `/favicon.png`,
`/~partytown/partytown-sw.js`, and a `/link-card-images/` URL. Use Wrangler rather
than Astro preview, which does not apply Cloudflare's `_headers` rules.
